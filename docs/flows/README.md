# 機能別処理フロー資料

成果物は [feature-flows.html](../feature-flows.html)。ブラウザで直接開ける、外部通信不要のHTMLです。

- 12機能の担当別フロー、ステップ詳細、DB更新、失敗・再試行、API対応、設計変更候補。
- 全体像・データ関係・実装順を含む15ページ構成。左の目次、図のステップ、前後ボタンで移動します。
- 「全ページを印刷 / PDF保存」で全機能を出力できます。印刷版は各ステップの説明を展開します。
- 「実装あり」は静的コード確認のみ。APIの動作確認や本番稼働を表しません。

## 更新方法

1. 仕様の変更は要件/APIの正本で先に確定する。
2. `content.mjs` の機能・ステップ・API・現状・未確定事項を更新する。
3. 必要に応じて `viewer.js` の全体像・データ・実装順も更新する。
4. リポジトリルートで `node docs/flows/build.mjs` を実行する。
5. 出力HTMLを開き、目次・ステップ・印刷を確認する。

`style.css` は資料固有のレイアウト。生成時にインストール済みdaisyUIのCSSを同梱します。閲覧時にはNodeやNext.jsサーバは不要です。ファイルの編集元と成果物を一緒に管理してください。

`verify.cjs` はPlaywrightとEdgeのヘッドレス実行で、15ページ・83ステップの移動、図の枠の重なり、モバイルでの本文のはみ出し、外部通信なし、印刷用全ページの生成を検証します。`node docs/flows/verify.cjs <Playwrightパッケージの絶対パス>` で実行でき、確認用画像と印刷PDFはGit管理対象外の `qa/` に出力します。スマホでは処理図とAPI表の領域内を横スクロールできます。

ソースへのリンクは、2リポジトリを隣接配置した場合に有効です。HTML単体で共有しても図と説明は動作しますが、ソース自体は同梱していません。リンク先のコードは後の変更で変わり得ます。
